# aio-apps — micro-app catalog

Catalog for AIO micro-apps: bundles, a review checklist, and CI that turns a submission into
a signed `registry.json` plus immutable `artifacts/*.zip`.

## Use it from AIO

AIO → **Store → Online catalog**:

| Field                                 | Value                                                                 |
| ------------------------------------- | --------------------------------------------------------------------- |
| Registry URL                          | `https://cdn.jsdelivr.net/gh/Atom112/aio-apps@registry/registry.json` |
| Publisher public key (base64 ed25519) | `9u2f5E2YBdmETe2+GoutiQq9WkhgZcITAijhWpRhUfI=`                        |

The client verifies the ed25519 signature over the payload bytes, then sha256 of each
artifact before extracting it. A tampered payload fails before anything is downloaded.

`main` holds reviewed sources only; CI publishes `registry.json` and `artifacts/` to the
`registry` branch, so the reviewed branch never needs a machine commit. `raw.githubusercontent.com`
serves the same files and is the GitHub-native option, but some networks reset that host;
jsDelivr is the default for that reason. For reproducible installs replace `@registry` with a
release tag (`@v1.2.3`): jsDelivr caches branch URLs for hours, while tag URLs are immutable.

## Layout

```
aio-apps/
├── apps/<publisher>/<app>/   # bundles (aio.app.json + entry + icon/screenshots + SDK)
├── .aio-tools/               # vendored AIO gate + registry tool (do not edit by hand)
├── publisher.pub             # public half of the signing key (private half lives in CI)
├── REVIEW.md                 # what a reviewer checks, in order
├── pull_request_template.md  # submission checklist
├── revocations.json          # reviewed list of revoked versions (seeded into every build)
├── registry.json             # generated + signed by CI; do not edit
└── artifacts/                # generated zips referenced by registry.json
```

## Submission flow

1. Fork, add `apps/<publisher>/<app>/` with a valid `aio.app.json`.
2. Open a PR. CI runs `check-app-bundle.mjs` (structure, size, extensions, style contract)
   and builds an unsigned registry to prove the submission is buildable.
3. A reviewer works through `REVIEW.md`; the PR is the audit trail.
4. Merge to `main`: CI builds the bundles, signs `registry.json` with the `PUBLISHER_KEY`
   secret, verifies it, and commits both the registry and the artifacts back to `main`
   (`[skip ci]`), so raw URLs stay current.
5. Clients pick up the new index on their next refresh.

## Local checks

```bash
node .aio-tools/check-app-bundle.mjs apps
node .aio-tools/apps-registry-tool.mjs build --apps apps --artifacts artifacts --out registry.json
node .aio-tools/apps-registry-tool.mjs verify --in registry.json --pubkey "$(cat publisher.pub)"
```

## Signing and revocation

The signing key is a base64 PKCS#8 ed25519 key held only in the `PUBLISHER_KEY` repository
secret. Rotating it means publishing a new `publisher.pub` in the same PR that updates
clients (public keys are pasted by users, so rotation is a release note).

```bash
# revoke a version without deleting history: append to the reviewed list, then PR it
node .aio-tools/apps-registry-tool.mjs revoke --id io.example.app \
  --digest <artifact sha256> --reason "credential exfiltration"
git add revocations.json && git commit -m "revoke io.example.app 1.2.3" && git push
```

`revocations.json` is the durable source of `revoked[]`: every build seeds the index from it,
so a rebuild never resurrects a revoked version. CI re-signs after the PR merges.

Installed clients disable the matching version on the next refresh (by digest or id+version)
and show the reason; uninstall stays available.

## Governance

- `main` is protected: no direct pushes, one approving review (CODEOWNERS), and the `verify`
  check must pass. Generated output never lands on `main`; CI force-pushes it to the
  unprotected `registry` branch.
- Signing runs only in the `production` environment, which requires manual approval. The
  `PUBLISHER_KEY` secret exists **only** there; a normal PR run never sees it.
- Reviews follow `REVIEW.md`; `CODEOWNERS` requests the owner on every submission.
- Releases are tagged (`vX.Y.Z`). Point clients at a tag for an immutable snapshot:
  `https://cdn.jsdelivr.net/gh/Atom112/aio-apps@vX.Y.Z/registry.json`; `@main` tracks the latest
  signed index.
- Incidents: see [SECURITY.md](SECURITY.md) — revocation is an index change, never a silent
  deletion.

## Policy

- A PR may add new versions; the previous version stays indexed for rollback.
- Removing a version is expressed as `revoked`, never as a silent deletion.
- `updatedAt` is generated by CI; never hand-edit it.
